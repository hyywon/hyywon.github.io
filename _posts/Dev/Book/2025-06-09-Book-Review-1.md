# 1장. 들어가며

## 코딩만 할 줄 아는 주니어, 이제 실무 준비 시작 🚀

“코딩은 할 줄 아는데, 왜 서비스가 점점 느려지고 문제는 계속 생길까?”

많은 주니어 백엔드 개발자가 한 번쯤 겪는 고민입니다.

코딩은 시작일 뿐, 실제로 운영 환경에서는 시스템이 어떻게 돌아가는지, 문제는 왜 생기는지 이해하는 게 훨씬 중요하다.

---

### DB 커넥션 누수와 커넥션 풀 이야기 🔌

`connection` DB와 연결하는 ‘커넥션’이라는 자원

이걸 제대로 관리하지 않으면 커넥션이 쌓여서 서비스가 느려지거나 멈출 수 있다.

Spring 프레임워크 덕분에 커넥션 반환 문제는 많이 줄었지만, 커넥션 풀 설정을 잘못하면 DB 연결 자체가 막힐 수 있으니 주의해야 한다.

---

### 성능 점검 리스트 📝

- 보안에 취약한 코드를 작성하지 않았는지
- 처음엔 잘 돌아가다가 시간이 지날수록 서비스가 느려지진 않았는지

⇒ 여러 프레임워크를 다룰 줄 알아도, 서버 운영에 필요한 기본 지식이 부족하면 운영 환경에서 문제 발생 가능성이 커진다.

# 2장.  느려진 서비스, 어디서부터 봐야 할까

## 처리량과 응답 시간

서비스가 느려질 때 가장 눈에 띄는 건 보통 조회가 10초 이상 걸리는 경우

이렇게 오래 걸리면 타임아웃 에러도 발생하니까 문제를 빨리 찾아야 한다.

보통 사용자는 무언가 실행할 때 걸리는 시간, 즉 **응답 시간**으로 서비스 품질을 판단한다.

(하지만 실제 성능에 영향을 주는 요소는 네트워크 속도, 디스크 속도, 메모리 크기, CPU 속도 등 다양)

### 서버 성능에서 중요한 두 가지 지표

- **응답 시간 (Response Time) :** 사용자의 요청이 처리되어 응답이 돌아올 때까지 걸리는 시간
- **처리량 (Throughput) :** 시스템이 초당 얼마나 많은 요청을 처리했는가?

---

## 응답 시간이란? **⏱️**

응답 시간은 사용자가 요청을 보내고, 서버에서 처리 및 응답을 줄 때까지 걸리는 전체 시간을 뜻한다.

**응답시간은 아래 두가지로 나누어서 측정 가능**

- **TTFB (Time To First Byte)** : 서버가 응답 데이터 첫 바이트를 보내는 데 걸리는 시간
- **TTLB (Time To Last Byte)** : 서버가 응답 데이터 마지막 바이트를 보내는 데 걸리는 시간

데이터 크기가 작으면 둘 차이가 별로 없지만, 큰 파일 전송 시엔 TTLB가 더 길 수 있다.

그래서 서버 성능 평가 시에는 데이터 특성과 네트워크 환경을 고려해 적절한 지표를 골라야 한다.

---

### 서버 처리 시간은 어떻게 구성될까?

서버 처리 시간은 다음 작업들로 나눌 수 있다.

- 로직 수행 (조건문, 반복문 등)
- DB 연동 (SQL 실행)
- 외부 API 호출
- 응답 데이터 생성 및 전송

보통 DB 연동과 외부 API 호출이 가장 큰 비중을 차지 ✅

```markdown
예시) 
전체 처리 시간: 348ms
- API 연동1 (외부 네트워크 API 호출): 186ms
- API 연동2 (외부 네트워크 API 호출): 44ms
- DB 연동(SQL 6회 실행): 101ms
- 로직 수행: 17ms
```

---

### 응답 시간이 서비스에 미치는 영향 **📉**

- 100ms 지연되면 검색 횟수가 0.2% 감소
- 400ms 지연되면 검색 횟수가 0.6% 감소
- 지연시간이 길어질수록 트래픽과 매출이 줄어들 가능성 높다.

응답 시간을 줄인다고 무조건 매출이 오르는 건 아니지만, 길어지면 분명 서비스에 악영향을 준다.

---

## 처리량 (Throughput)

서버 성능 측정 시 흔히 쓰는 단위로, 초당 처리할 수 있는 작업량을 뜻한다.
보통 **TPS** (초당 트랜잭션 수)나 **RPS** (초당 요청 수)로 나타낸다.

- 최대 TPS는 서버가 동시에 처리할 수 있는 최대 요청 수를 의미
    - 예를 들어, 서버가 동시에 5개 요청을 처리할 수 있고, 요청당 처리 시간이 1초면 최대 TPS는 5
    - 만약 동시에 7개 요청이 들어오면, 5개만 바로 처리되고 2개는 대기하게 돼서 응답 시간이 길어지게 됨

---

### TPS를 높이는 방법 **📈**

1. 서버가 동시에 처리할 수 있는 요청 수 늘리기 (대기 시간 줄임)
2. 요청 처리 시간 자체를 줄여 대기 시간 줄이기

✨ 효과적인 성능 개선법은 먼저 **트래픽 많은 시간대의 TPS와 응답 시간을 측정**하고, 이를 바탕으로 목표치를 정하는 것!

---

### TPS 확인 방법 **👀**

- 모니터링 도구 활용: 스카우터, 핀포인트, 뉴렐릭, 엘라스틱서치 등
    - 실시간 TPS, 과거 특정 시점의 TPS 확인 가능
- 모니터링 도구는 근사치를 이용하는 경우가 많음 (예: 5초 간격 처리 요청 수 나누기 5)
- 더 정확한 TPS가 필요하면 웹 서버 접근 로그를 분석하면 됨
- 도구가 없을 땐, 리눅스 명령어와 간단한 코딩으로 로그 파싱도 가능!
